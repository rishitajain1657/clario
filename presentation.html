03 // CORE INNOVATION & PHILOSOPHY

Triage Engine, Not a Chatbot.

Most teams make the mistake of creating another chat window. Clario builds an automated, intelligent filter that delivers Five Daily Priorities.

THE BOT TRAP

Generic AI Chatbots

Requires students to formulate complex prompts. Hallucinates missing venues and times. Treats every announcement in total isolation.

  • Passive; waits for query
  • Hallucinates unverified dates
  • Ignores existing class timetable
THE CLARIO SHIELD

Automated Triage Engine

Proactively processes flyer posters, chats, and syllabi. Detects timetable conflicts and serves a strict 5-priority briefing.

  • Proactive clash detection
  • Strict grounding (No fake venues)
  • Preserves student autonomy
ZERO OVERWHELM

Five Priorities Rule

Never dumps 30 items. Ranks the top 5 urgent student items with consequences clearly explained so students remain in control.

  • One-click dashboard sync
  • Categorized urgency radar
  • Direct action checklist
Core Principle // Human Agency First Clario never decides for the student; it empowers them.

04 // SYSTEM ARCHITECTURE & PIPELINE

The Three-Stage Intelligence Pipeline.

Built with speed and certainty. Ingests multimodal noise and translates it into synchronized campus actions in milliseconds.

STAGE 01 // INGESTION

Multimodal Parser

Accepts flyer photos, syllabus PDFs, and forwarded WhatsApp chat logs.

  • Vision OCR for posters
  • Multi-format (.pdf, .png, .txt)
  • Unstructured text cleanup
STAGE 02 // TRIAGE

Collision Engine

De-duplicates repeated forwards and checks time against active timetable.

  • Automated overlap detection
  • Fingerprint de-duplication
  • Missing venue warning flags
STAGE 03 // ACTION

Campus Sync

Instantly binds extracted action points into the student's personal dashboard.

  • Checkable action radar
  • Persistent local JSON DB
  • Extensible Gemini API layer
Full-Stack Implementation // Node.js + Express + Multer + Gemini AI Tested on Real Campus Datasets
